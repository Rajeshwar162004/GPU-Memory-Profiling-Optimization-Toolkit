Section B — Bottleneck Classification & Diagnosis

Classification
🔥 MEMORY-LIMITED / MEMORY-INEFFICIENT
[HIGH] Potentially Inefficient / Uncoalesced Global Memory Access
Evidence: Memory is more heavily utilized than Compute: Look at the Memory Workload Analysis section to identify the L2 bottleneck. Check memory replay (coalescing) metrics to make sure you're efficiently utilizing the bytes transferred. Also consider whether it is possible to do more work per memory access (kernel fusion) or whether there are values you can (re)compute.
Explanation: Threads in a warp are accessing global memory addresses with large strides or non-contiguous layouts. This forces the GPU memory controller to issue multiple 32-byte cache line transactions for a single warp instruction, wasting memory bandwidth.
[HIGH] Kernel Bottleneck: Memory-Bound Execution
Evidence: Memory throughput (67.5%) significantly dominates compute pipeline utilization (5.1%).
Explanation: Execution speed is constrained by GPU memory bandwidth or access latency rather than arithmetic processing power. Optimizations should focus on data reuse, coalescing memory reads/writes, and leveraging shared memory.

Section C — Recommended Optimizations

Reorganize Thread Indexing for Global Memory Coalescing
Ensure contiguous threads in a warp access contiguous memory locations (unit stride).
// Before (Strided Access):
output[x * height + y] = input[y * width + x];

// After (Coalesced access via Shared Memory Tiling):
tile[threadIdx.y][threadIdx.x] = input[y * width + x]; // Coalesced load
__syncthreads();
output[y_out * height + x_out] = tile[threadIdx.x][threadIdx.y]; // Coalesced write
Reduce Memory Traffic & Increase Arithmetic Intensity
Kernel execution speed is bound by memory bandwidth. Combine operations (kernel fusion) or compute values on-the-fly where possible.
// Kernel Fusion: Combine vector addition and scaling into a single kernel pass
c[i] = alpha * a[i] + beta * b[i];
